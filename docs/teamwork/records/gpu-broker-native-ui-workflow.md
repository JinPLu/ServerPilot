# Record: 原生 macOS GUI 公开 copy 与语言层级收束

## Current synthesis

- Subject identity: 原生 macOS GUI 公开 copy 与语言层级收束这一持续目标

本次讨论把 ServerPilot 原生 macOS GUI 的公开 copy 收束为一套短、专业、高密度的语言层级，覆盖导航、资源卡片、项目与 Agent、分配表单、详情与本机设置。正常状态只给事实，不追加解释性段落；异常直接写出可行动的具体原因。以下三项选择已由用户定下，替代此前的候选推荐：导航使用「服务器 / 使用情况 / 设置」；主操作使用「申请 GPU」；保活作为「占卡」功能呈现。

## Settled direction and boundaries

- 可被调度的 GPU 统一称为「空闲」，不再以「可用」表达该事实。
- GPU 被 Agent 归属或使用时，展示「项目 · 任务 · Agent」关系，不使用泛化的状态标签。
- 没有关联 Agent 的进程占用统一称为「任务占用」。
- 「占卡」表示 Broker 有意持有 GPU 的占用功能；占卡 GPU 不是「空闲」，不能进入可调度集合。其状态/任务名统一为「占卡」，让后续 Agent 能识别并执行受控停止或中断。
- 停止「占卡」只能走受控停止路径，不得演化为任意远程任务 kill；内部 KEEPALIVE 实现词不进入公开 copy。
- 连接或采集失败必须显示具体原因（例如连接超时、认证失败或采集失败），不使用「状态异常」等空泛文案。
- 禁用「待处理」「需关注」「状态异常」等泛化状态词；预约、等待队列、维护、draining 等公开流程已移除，相关旧文案应一并删除。
- 保留 REST/领域事实边界、GPU UUID 与 endpoint 身份边界、原生 SwiftUI/AppKit 表面与 operator-density/accessibility/Reduce Motion 要求；本次只记录 copy 方向，不改产品代码。

## Emerging language hierarchy

1. 导航层：顶层使用「服务器 / 使用情况 / 设置」，不再使用「资源 / 项目与 Agent / 本机设置」或把第二页称为「资源分配」。
2. 资源事实层：用「空闲」表达可分配；用「任务占用」表达无 Agent 关系的进程占用；用「占卡」表达 Broker 有意持有且不可调度的 GPU。
3. 归属关系层：有 Agent 归属时优先展示「项目 · 任务 · Agent」三段关系，而不是抽象的「状态」。
4. 操作层：用户选择的主操作是「申请 GPU」，释放动作是「释放 GPU」。当前后端仍是即时成功/失败，不能让「申请」带回预约、审批或排队流程；结果 copy 需要直接说明成功或具体失败。
5. 失败原因层：以连接、认证、采集等具体原因作为主文案；必要时补充重试或修复动作。
6. 技术设置层：KEEPALIVE、Schema、control-plane、受控采集协议等实现术语不进入普通资源详情；只有在设置中确有运营价值时，才换成操作者可理解的中文说明。

## User-settled choices and consequences

### Navigation

用户选择「服务器 / 使用情况 / 设置」。它更直接地按操作者任务组织信息，也解决了「资源分配」作为第二页名称过于动作化的问题。后续页面标题、侧栏、空状态和返回路径必须使用同一组名词；旧的「项目与 Agent」不再作为顶层导航名，但可继续作为归属关系字段。

### Primary action

用户选择「申请 GPU」，即使当前后端没有排队。该词必须与即时结果配套，不能暗示预约、审批或等待队列：成功、已占用、连接/采集失败都应在原处写清事实和原因。「释放 GPU」作为对称释放动作。

### Occupation feature

用户选择公开呈现「占卡」，隐藏内部 KEEPALIVE。占卡是 Broker-owned 的故意 GPU 占用，不是 Agent 任务，也不是空闲资源；状态和任务名都写「占卡」，后续 Agent 可据此识别。停止/中断按钮必须调用受控停止路径，不能提供任意远程任务终止语义。普通资源详情只显示与当前操作有关的占用事实；具体入口位置仍需逐屏落定。

## Audit observations requiring copy cleanup

- 资源 claim sheet 仍声称资源会排队；等待队列流程已移除，应保留「申请 GPU」这个动词但改成即时成功/失败结果，不恢复排队叙事。
- 删除确认仍出现 pause/drain 语义；维护、暂停、draining 不是当前公开流程，应删除这些提示。
- GPU 指标仍有「可用」；应改为「空闲」，并从空闲统计中排除「占卡」。
- 筛选器仍使用「不可分配」「关注优先」等泛化标签；需要改成事实或具体原因。
- 本机设置仍暴露 Schema/control-plane 术语；新增服务器表单仍暴露「受控采集协议」和过长的 Docker 免责声明；这些都需要压缩为面向操作者的中文 copy。
- 普通详情不应暴露 KEEPALIVE；如需操作占卡，应显示「占卡」及受控停止动作，不显示实现名。
- 页面标题、侧栏和返回路径还需清理残留的「资源」「项目与 Agent」「本机设置」「资源分配」混用，统一到用户选择的导航名词。

## Material options and comparison

### Navigation nouns

- 选项 A：「资源 / 项目与 Agent / 本机设置」。保留资源事实与归属语义，改动面小，但第二页与「资源分配」混用已经造成任务路径歧义。
- 选项 B：「服务器 / 使用情况 / 设置」。任务导向更直接，减少实现和领域层级泄漏；代价是 Agent 归属必须在页内字段表达，不能由顶层导航承载。

用户选择 B；后续 copy 应按 B 收束，不再把 A 作为并列公开方案。

### Primary action

- 选项 A：「分配 GPU / 释放 GPU」。更贴近资源状态转移，但会把操作描述成已完成的分配。
- 选项 B：「申请 GPU / 释放 GPU」。保留用户熟悉的请求动作，但若不补即时结果，容易被误读为排队或审批。

用户选择 B；结果必须通过成功/失败和具体原因消除队列歧义。

### Occupation terminology

- 选项 A：隐藏技术词并只在服务器设置提供保活控制；普通详情仍只写任务占用。
- 选项 B：普通详情公开「系统任务/保活」；实现机制可见，但污染资源语境。
- 选项 C：以用户可理解的「占卡」呈现 Broker-owned 占用，隐藏 KEEPALIVE，并提供受控停止/中断。

用户选择 C。占卡不是空闲，不能和 Agent 任务或任意远程进程混写。

## Current recommendation

以用户已定下的「服务器 / 使用情况 / 设置」「申请 GPU / 释放 GPU」「占卡」为全局词表，按「资源事实 → 归属关系 → 操作结果 → 具体失败原因」重写全屏、详情、筛选、分配、删除确认和设置 copy。先清理已移除流程的 queue/pause/drain 文案，再逐屏收敛失败短句、占卡入口和设置说明。不要把内部 KEEPALIVE、Schema 或 control-plane 作为用户术语。

## Final screen-copy contract (user confirmed)

- 页面标题为「服务器」；顶部显示数量与 GPU 型号，窄屏可隐藏型号；更新时间只写「更新于」和时间。
- 页面动作固定为「添加服务器 / 申请 GPU / 刷新」。
- 常驻快速筛选固定为「全部 / 有空闲 GPU / 任务占用 / 占卡 / 连接失败」。
- 宽屏每次进入详情默认关闭 inspector；只有点击服务器后打开，不自动选中服务器，也不恢复上次选择。详情在窄屏切换为全页并保留返回路径。
- 表格列固定为「SSH / 项目·任务 / GPU 配置 / 空闲 / GPU / 显存 / CPU / 内存」。
- 数字保持中性；meter 使用颜色表达量级；只有当前排序列显示箭头。
- 正常 SSH 不显示在线副文；异常 SSH 显示具体连接或采集原因。
- 当前使用行显示任务、项目·Agent、GPU 数量和「释放」动作；无 Agent 关系的进程显示「任务占用」，Broker-owned 持有显示「占卡」。
- 添加服务器只提供一个「SSH 指令」粘贴字段，自动解析 host、port、user；常态只显示字段和按钮，解释仅用于字段错误；不把受控采集协议或 Docker 长免责声明作为常态表单 copy。
- 「申请 GPU」表单只保留「项目、任务、GPU 数量、服务器」四项；常态只显示字段和按钮，解释仅用于字段错误；移除「用途」以及 CPU、内存、显存阈值字段。
- 设置页只公开「本机服务地址 / 数据更新间隔 / 版本」；数据更新间隔只提供 5/10/30 秒预设，实现时必须同步超时判断；Schema、control-plane、KEEPALIVE 等技术细节不进入常态界面。
- 历史、详情、使用情况和对话框沿用同一事实优先词表：常态只给事实和更新时间；解释文字只用于错误、空态和破坏性确认；错误必须写具体连接/认证/采集原因；删除确认不得再出现 pause、drain、维护或暂停叙事。
- 「占卡」的停止或中断只能调用受控停止路径；不得提供任意远程任务 kill 语义。

## Server detail contract (user confirmed)

- GPU 使用紧凑列表，不使用 GPU 卡片，也不只给汇总数字。
- 详情直接外露「申请 GPU」和「占卡」；编辑 SSH、删除服务器收纳在更多菜单。
- 结束占卡只放在对应的「占卡」记录中，不提供服务器级停止入口；仍必须调用受控停止路径。
- 历史图默认展开。
- 正常详情只显示更新时间；异常时在标题下显示唯一一条具体错误，不叠加泛化提示。
- 指标一行平铺，信息顺序固定为「当前数字 → 每张 GPU → 当前使用 → 历史」。
- 详情继续遵循自适应主从：宽屏右侧 inspector，窄屏全页详情并保留返回。

## Layout and sidebar direction (user settled)

- 主从布局采用自适应方向：宽屏使用右侧 inspector；窄屏切换到全页详情，并保留明确返回路径。
- 常态只展示事实；解释文字只用于错误、空态和破坏性确认。
- 侧栏常态只显示产品名，以及「服务器 / 使用情况 / 设置」；底部区域仅在发生异常时显示具体错误，不显示泛化提醒或技术状态。
- 布局总方向已经确定，但逐屏 inspector 内容、全页详情层级、返回路径和具体 copy 仍在 collaborating 中。

## Agent identity and communication frontier

### Observation and local evidence

用户判断当前 Agent 本身没有足够产品价值：稳定的工作身份是「项目 + 任务」，Agent 的唯一应有价值是帮助 Agent 间通信，并且必须真正做到。当前本地证据显示 gpu_coordination 的 docstring/实现是只读；actor 只有身份、项目和资源记录；API/MCP 没有发送消息、读取 inbox、thread address 或打开 Agent 的能力。因此 UI 不应先加入虚假的「联系 Agent」入口或把 Agent 作为一级浏览视角。

### Product boundary (global rule)

- GUI 完全不管 Agent 协调地址：不展示链接、按钮、Agent 页面、消息区、聊天、收件箱、未读或发送框；申请 GPU 表单也不新增 URI 字段。
- 「项目 + 任务」是唯一稳定工作身份；Agent 只作为执行者/协调入口显示，不作为一级浏览维度。
- Agent 调用 MCP 时自动登记自己的 Codex task URI；MCP 协调读把对方 Actor 与 URI 返回给 Agent；Agent 按 global rule 自行通过 Codex 联系。该登记/返回能力是未来实现要求，不是 GUI 功能。
- 使用情况页只按项目/任务浏览，默认项目视角已确定。

### Usage page confirmations

- 顶部汇总显示当前任务与 GPU，默认项目视角，可切换任务；GUI 不显示 Agent。
- 空态只显示一句话和「申请 GPU」按钮，不添加自我解释段落。

## Confirmation copy (user confirmed)

- 删除服务器：标题「删除这台服务器？」；仍有 GPU 正在使用时显示「仍有GPU正在使用时不能删除」。
- 释放 GPU：标题「释放N张GPU？」；正文「请先确认任务已结束。释放不会停止任务」。
- 结束占卡：标题「结束占卡？」；正文「将释放这张GPU」。

## Accepted scope and execution frontier

本轮 accepted/finalize 的范围是上述 GUI 词汇、事实优先叙述、服务器/使用情况/设置导航、申请/释放/占卡动作、自适应主从布局、服务器详情结构、使用情况项目视角与确认框 copy。UI 代码尚未实现；MCP 调用自动登记 Codex task URI、协调读返回 Actor+URI 也尚未实现，属于下一执行阶段，不构成当前 GUI 完成声明。

## Unresolved decisions

- 设置页与添加服务器/申请 GPU 表单的逐屏位置、间距、字段错误短句和响应式细节仍待执行阶段确认。
- UI 代码与 MCP URI 自动登记/协调读尚未实现；下一阶段需按本记录验证实现，不把未实现能力写成已完成。

## Return path

本轮 GUI 词汇与布局方向将通过 accepted-decision 事务封存；设置/表单逐屏细节以及 UI 与 MCP 实现留在下一执行阶段。
