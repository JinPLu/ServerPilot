# 归还即结束进程、Agent 清理无人任务、30 秒平均

2026-11-10。用户提出 MCP 引导、Agent 清理权限、App 归还、菜单栏、平均值、配色和服务器页布局七点，其中三点改变了既有约定，由用户选定方向。

## 用户的问题（原话）

> Agent的权限也有些过低了，如果遇到错误的程序没有注册的情况下，或者说已经废弃的项目或者agent进程，我开一个新的agent窗口的时候，无法删除清理相关的任务。此外人类在app上的操作也不太方便，如果我要杀死一个任务或进程的时候，点击归还的时候应该把进程也杀死，而不只是把任务注销掉。

> 在服务器界面上的计算资源使用情况是瞬时的，这个难以体现正常的使用情况，我希望是平均的。

## 用户的决定

| 问题 | 用户选择 |
| --- | --- |
| App 里点“归还”时要不要同时结束卡上的进程？（此前的边界是 ServerPilot 不停止用户程序） | 确认后结束（推荐）：弹窗列出进程，确认后先 SIGTERM，10 秒后仍在再 SIGKILL；只结束 SSH 账号自己的进程，逐个回报结果。 |
| 新开的 Agent 清理别的项目留下的任务，权限放多宽？ | 确认无人在用才可（推荐）：持有者超过一段时间没有心跳、且卡上没有正在跑的进程时，任何 Agent 都能归还；卡上还有进程就请人类在 App 里处理。 |
| 服务器页的用量取多长时间的平均？ | 用户在选项之外写了“最近三十秒”。 |

## 解读与落地

- “归还”从只改账本变成结束工作，这是项目第一次结束不是自己启动的进程，所以范围收得很窄：只结束采集记录里这个任务卡上的进程，动手前在服务器上核对重启标识、启动时间和账号 uid，任何一项不符就跳过并写明原因。Agent 自己归还任务不结束进程。`AGENTS.md`、两份 README 和设计契约的边界句已改写。
- “无人在用”没有另立标准，用的是 App“释放空闲占用”已有的判据，也就是持有者在 `idle_lease_alert_seconds`（默认 10 分钟）内没有任何存活迹象，并且卡上没有进程。另外加了一条限制：Agent 不享有“服务器失联时由人决定”的豁免。
- 30 秒短于持久化历史的间隔（每分钟一点），所以平均值在内存里算。它只给人看；Agent 和准入仍读最新一次采集与 10 分钟平均。
