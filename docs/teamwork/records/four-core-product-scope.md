### 2026-08-12 — legacy case-decision 原件（12:10）并入

##### 已确认决定

ServerPilot 的产品范围只保留四个核心功能，并要求四项形成完整、通畅、简洁的链路：

1. 采集事实：采集资源、任务、GPU 与连接事实。
2. 人类监控 APP：实时显示这些事实、更新时间、任务-GPU 关系及具体冲突或错误。
3. Agent 操作：Agent 申请 GPU、把任务指派到选定 GPU、释放 GPU。
4. 占卡：支持空闲 GPU 的占卡与按卡让渡，并把占卡/任务占用作为可见事实。

这里的“绑定”仅指任务与 GPU 的操作性指派关系；它不引入 attestation、绑定证明或其他校验控制。

##### 人工纠错与冲突边界

两个任务占同一 GPU 等真实冲突交给人类实时监控 APP。APP 必须提供明确纠错和任务-GPU 腾挪：人可以自由重新指派哪个任务使用哪个 GPU，并解除占用冲突。不得用自动调和、自动抢占或其他新增自动防御替代人的实时判断。

##### 服务器事实

用户明确未使用的服务器永久删除，不保留 retired 等附加状态。<内网主机> 已重新导入并处于 active/online。

##### 被明确否定或取代的既有内容

以下内容不属于新范围，不能悄悄保留、改名或以等价机制复活：

- fail-closed；
- attestation、用于校验/证明的 binding，以及 SHA-256 或任何替代哈希机制；
- STARTING、STOPPING、retired、legacy-stop-required 等额外状态或生命周期；
- 自动调和、自动抢占式控制；
- 哈希迁移、随机 task identity 以及其他未确认设计。

四个核心功能之外不增加状态、生命周期、迁移或防御式/预防式控制。不重复造轮子：复用已确认的事实与操作边界，不引入等价替代机制。

##### 实施边界

以上是产品决定，不是实现完成声明。当前代码、测试和验证状态留给执行阶段确认；未确认的逐屏交互、路由或其他设计不在本决定中。

##### 事实输入

- 用户明确未使用的服务器应永久删除，不保留 retired 等额外状态；<内网主机> 已重新导入并处于 active/online。
- 诊断发现 per-GPU 占卡在启动失败后会泄漏 HELD/STARTING；后续调和跳过该占用，申请因此永久 no_capacity；旧整机占卡又产生 LEGACY_STOP_REQUIRED。
- 当前修复范围已暴露四类功能中的现有断点：信息采集、人类监控、Agent 操作、占卡；还包括 endpoint 事件对 human 不可见、CLI 死路由/缺 observed bind、client 重算 coordination、GUI no_capacity/KEEPALIVE 语义错位，以及 SHA-256 与随机 task identity 违约。

##### 当前综合

产品最小形状由四个核心功能组成：

1. 采集事实：从受管端点采集并保留资源、任务、GPU 与连接事实。
2. APP 实时显示：人类监控 APP 直接展示当前事实、更新时间、任务与 GPU 关系及具体冲突/错误。
3. Agent 操作：Agent 可以申请 GPU、将任务绑定到选定 GPU、释放 GPU；“绑定”在此仅表示任务-GPU 的操作关系，不表示 attestation 或其他验证控制。
4. 占卡：支持空闲 GPU 的占卡与按卡让渡；占卡和任务占用作为可见事实交给 APP 与 Agent 处理。

真实冲突（例如两个任务指向同一 GPU）交给人类实时监控 APP。APP 必须提供明确纠错：人可以自由重新指派任务与 GPU、解除占用冲突并完成任务-GPU 腾挪。系统不通过新增自动防御来掩盖或替代这一人工决策。
