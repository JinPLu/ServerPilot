# ServerPilot 桌面设计系统

本文是 macOS App 的界面契约。目标不是展示最多字段，而是让用户在较低认知负担下完成三件事：**看清资源、申请资源、追溯归属**。

## 1. 产品边界

- 单用户、本机控制面、多服务器、多 Agent。
- App 是观察与操作界面，不是聊天工具，也不是任务执行器。
- 工作身份显示为“客户端 · 项目 · 任务”，让人知道是谁在占卡。GUI 不做 Agent 间消息或聊天。提醒页和菜单栏是产品入口，不是消息收件箱。
- 资源真相来自同一 REST 状态；界面不得自行用“容量减用量”推算可分配资源。

## 2. 视觉原则

### 仅浅色

- App 固定使用浅色外观，不跟随系统深色模式。设计令牌用语义名，加深色时不用改页面。
- 主要内容一律不透明。**只有侧栏是半透明的**（系统 `sidebar` 材质）：导航退到桌面上，承载数据的表面保持清晰。禁止全窗毛玻璃、背景图片、渐变光晕和大阴影，也不给表格、方块、卡片加玻璃。
- 只有两个平面：内容表面 `#FFFFFF`，页面底色 `#F2F2F5`，相差 1.12:1，是 Apple 分组背景的步进，底色不带蓝。层级靠这一步、间距与字重，不叠第三层。「增强对比度」开启时底色加深，并给所有方块描边。
- macOS 使用原生控件与 SF Symbols，不创建第二套产品语言。

### 颜色只留给该看的东西

- 一台服务器一切正常时，这一行应当安静。**空闲的卡是空心方块，实心表示卡上有东西**：运行中蓝、已分配未运行灰、外部进程橙、归属冲突红、数据过期浅灰。
- 压力柱和小曲线平时是中性灰，超过阈值才变色：`<70%` 灰 / `<90%` 橙 / `≥90%` 红。数字同样在 70% 以上才变色。
- 服务器方块只在异常时整块染色：连接失败用红色浅底，外部进程等需要留意的状态用橙色浅底。

### 每页只回答一个问题

| 页面 | 问题 | 形态 |
| --- | --- | --- |
| 总览 | 现在什么情况，有什么要我处理 | 状态胶囊 + 容量/趋势/待处理 + 按组排列的服务器方块 |
| 服务器 | 哪台机器现在能给我卡 | 对齐的表格 |
| 任务 | 谁在用，有没有风险 | 每个任务一张卡，需要留意的在前 |
| 菜单栏 | 要不要打开 App | 总览的缩小版 |

- 页面标题直接落在页面底色上，不再有白色工具栏带。白色只属于卡片、方块和表格。
- 一张 GPU 在所有页面都是一个方块（`CardPip`），文字由 `CardVocabulary` 决定。
- 后台轮询不得引起可见变化：刷新按钮只响应人的操作，不旋转、不变灰。

### 总览用方块，比较用表格

总览回答「整体如何」，用按组排列的方块，一眼看全局。服务器页回答「哪台能给我卡」，这是跨机器比较的问题，只有对齐的列能让眼睛顺着往下扫，所以它始终是表格，不换成方块网格。

- 服务器表一台服务器一行 50 pt，两行内容：地址与状态、任务与持有者。整表装进一张圆角 16 pt、无描边的卡片。
- 窄窗口靠**从右折叠列**适配，不切换成另一种行结构。地址车道有硬下限 200 pt。四项指标任何档位都不折叠；可以折叠的只有 `每张卡` 与 `任务`，这两项在行 tooltip 和详情弹窗里各有一份。
- 正常状态让数字和短标签承担信息；解释性句子只用于错误、空状态和不可逆确认。
- 主要值完整优先，次要说明才可截断。悬停帮助与辅助功能名称保留完整语义。

## 3. 设计令牌

### 颜色

| 用途 | 颜色 | 规则 |
| --- | --- | --- |
| 空闲 / 正常（深层） | `#00832F` | 状态点、容量环、图标与状态短语。压力柱不用绿色 |
| 注意 / 中压力（深层） | `#B05A00` | 状态点、进度柱、环弧、图标与状态短语 |
| 错误 / 高压力（深层） | `#E40021` | 同上 |
| 低压力柱、静止的小曲线、已分配未运行的卡 | `#8E8E93` | 中性，让颜色只出现在异常上 |
| 空闲的卡（描边） | `#A8ACB4` | 空心方块 |
| 数据过期的卡 | `#E5E5EA` | 看不到的卡不抢眼 |
| 正常 / 注意 / 错误（浅层） | `#E7F8EB` / `#FFF1E5` / `#FFE7E8` | 只作区域底色，其上内容用中性色 |
| 占卡 / 已持有 | `#5B616B` | 中性，避免随用户强调色浮动 |
| 轨道 | `#E5E8EE` | 所有进度柱的未使用部分 |
| 交互 | macOS `controlAccentColor` | 主按钮、焦点、链接、运行中的卡和曲线 |
| 主文字 | `labelColor` | 标题、SSH、项目、任务、型号和数字 |
| 次文字 | `secondaryLabelColor` | 单位、辅助状态、时间和空值说明 |
| 轨道 | 中性浅灰 | 所有资源进度柱的未使用部分 |

数字保持中性色，70% 以上才随压力变色。颜色必须同时配合文字、图标或数值，不能独自传达状态。

状态色分两层。**深层**用于必须被读懂的记号——状态点、进度柱、环弧、图标和状态短语；它在内容表面（`#FFFFFF`）上实测 4.90 / 4.87 / 4.86，同时满足图形的 3:1 和正文的 4.5:1，因此可以安全地染文字。**浅层**只作区域底色，其上一律用中性文字。

把 3:1 强加到约 50pt² 的小色点上行不通：WCAG 对绿色加权 0.7152，该约束在近白底上数学地把绿逼成森林绿、把琥珀逼成芥末。Apple 自家 systemGreen 在页面底色上实测仅 1.79:1——它靠的是大面积浅色底加深色内容，以及色点旁边总有一个复述状态的词。本系统采用同一策略：浅层承担约二十倍于记号的面积，亮度由它给，可读性由深层给。

数字与句子保持中性色。调整色值时保持色相、重新测量两个平面，不得靠加大面积规避阈值。

### 字体

正文字阶下限为 11 pt（`annotation`），身份与命令 12 pt，行内数值 13 pt。字阶为七档 Apple 语义样式：`caption`(10) / `subheadline`(11) / `callout`(12) / `body`·`headline`(13) / `title3`(15) / `title2`(17) / `largeTitle`(26)。最大与最小之比 2.60，这是让某个元素能当主角的前提；此前的六档只跨 1.70，且 macOS 上 `footnote` 与 `caption2` 同为 10pt，实为重复档。

`largeTitle` 与 `display` 是展示档，**每屏各最多出现一次**。数字一律加 `.monospacedDigit()`——采集每几秒重绘一次，比例数字会让整列抖动。同屏字体只用 SF Pro 一族，圆体仅限展示档与卡片主值。实现侧由 `Typography` 令牌层提供角色名，界面代码中出现新的 `.system(size:)` 视为回归而非微调。


- 页面标题：`screenTitle`，26 pt bold，直接落在页面底色上。
- 总览的容量数字：`display`，42 pt，全 App 只此一处。
- 表头：11 pt，当前排序键加深。
- 行主值：`rowPrimary`，13 pt medium；行辅助值：`annotation`，11 pt。
- 地址、时间和数字用 tabular figures；完整 SSH 指令和 GPU ID 用等宽字体。
- 禁止为了“丰富”而给同一概念换词。

### 尺寸

- 8 pt 基础网格。
- 页面边距 16–20 pt；区块间距 12–16 pt；行内间距 6–10 pt。
- 表格行高紧凑，但整行点击区域不得小于 36 pt。
- 指标进度柱约 40 pt 宽，和数字并排。
- 圆角是一个四级刻度，不是区间：`4`（卡片方块、计数徽标）/ `7`（字段、图标方块）/ `10`（磁贴内的次级面板与弹窗分区）/ `16`（磁贴本身与页面级卡片）。按钮与筛选用胶囊。落在两级之间的值取较近的一级；十一种圆角读起来是漂移而不是系统。
- 装饰透明度同样收敛为五级：`0.04`（悬停微底）/ `0.08`（细线与分隔）/ `0.12`（图标方块与状态胶囊底色）/ `0.30`（选中或悬停描边）/ `0.55`（文字下方的强调底）。文字与材质自身的不透明度不受此约束。
- 磁贴静止时不描边，靠一层可见的平面差表达浮起；只有系统开启「增强对比度」时才补一条 1 px 边。无重阴影。
- 圆体字族（`design: .rounded`）只用于 `hero` 与 `cardValue` 两个角色；其余一律用系统默认字族，否则字重与字宽会在同一行里对不齐。

## 4. 信息架构

侧栏是半透明的悬浮面板，从上到下：

1. **总览**、**服务器**、**任务**、**提醒**
2. **服务器组**：每组一项，显示空闲卡数，点开就是这个组的服务器表。服务器组是这个产品的「房间」
3. **设置**，固定在底部

窗口宽度小于 1100 pt 时侧栏收成图标栏，服务器组隐藏。窗口标题、侧栏选中项和页面标题不得重复表达同一信息。

## 总览页

从上到下回答「现在什么情况」：

- **状态胶囊**：每种卡状态一个，只显示有卡的状态。胶囊同时是图例，点一下到服务器页并筛选。
- **容量**：圆环加 `display` 数字，说明共多少张、一次最多申请多少张。
- **GPU 利用率**：全部卡近 24 小时的平均，来自 `GET /api/v2/utilization-trends`。采集中断的时段折线断开，不补成 0。遥测只保留 1 天，所以没有更长的趋势。
- **需要处理**：最多 3 条未确认的提醒；没有时写「现在没有要处理的事」。
- **服务器方块**：按组排列，每块显示地址、状态、在做什么、逐卡方块和近 1 小时小曲线。点开进详情。

## 菜单栏

点状态栏图标弹出总览的缩小版：容量、需要处理、每台服务器的逐卡方块，以及 `申请 GPU`、`打开 ServerPilot`、退出。同样的词和同样的方块，看菜单栏和看窗口不会读出两种结论。

## 5. 服务器页

### 顶部

- 页面标题：`服务器`，旁边是 `更新于 HH:mm`
- 主要动作：刷新（图标）、`添加服务器`、`申请 GPU`
- 筛选胶囊：`全部 / 有空闲 / 使用中 / 占卡中 / 连接失败`，每个带当前服务器数
- 搜索占位：`搜索服务器、GPU、项目或任务`
- 排序菜单、批量移除、服务器组管理放在搜索右侧，是图标按钮，辅助功能名称完整
- 总数放在表格卡片底部的状态栏：服务器数、GPU 数、空闲数、型号汇总

`刷新`表示重新读取控制面的当前状态。服务器观测由设置中的 5 / 10 / 30 秒采集间隔驱动；刷新不伪造一次新观测。

### 表格信息层级

服务器页是表格，不是磁贴网格。每一行回答同一个问题：**这台机器现在能不能给我卡**；每一列回答的是**哪一台**。行高固定 50 pt，行与行之间只用发丝线，不用底色条纹。

有正式服务器组时，用分组段头横切同一张表，不要把服务器改成卡片或网格。段头只显示组的显示名和紧凑的空闲/总 GPU；组内行仍按当前列排序对齐。未分组的服务器固定在表末，段头使用可执行标签`未分组的服务器`，并提供`管理服务器组`。完整路径、环境说明和数据/权重描述不进 44 pt 行，也不进段头，只出现在服务器组管理和服务器详情。产品用语固定为`服务器组`，不要写成外部调度器的`集群`。

Slurm 服务器组有在线节点明细时只显示 GPU 分区的节点，不另列登录入口的「按需申请」行；
「按需申请」保留在组标题中。节点沿用同一张表的行高和列宽，状态用中文（空闲 / 部分占用 / 已占满 / 维护中 / 不可用），不显示 Slurm 原词。
节点行使用登录入口 `host:port / 节点名`，不伪造计算节点的直连端口；
未采集到的利用率显示 `—`，维护节点不显示可申请数字。
一组有多少行就显示多少行，整张表只有一个滚动条并填满窗口，不限制每组行数。
所有组上下排列、共享表头，不改成横向卡片或网格。

**列的顺序就是回答问题的顺序**

| 列 | 内容 | 可折叠 |
| --- | --- | --- |
| 服务器 | 第一行 `host:port`，工作区未设置时补告警三角；第二行色点 + 状态词，还有空卡时写 `运行中 · 2 张空闲`，委托集群写 `按需申请 · 一次最多 N 卡` | 否 |
| 任务 | 第一行任务名，第二行 `持有者 · 项目`；无归属时只写 `—`，不打印「无运行任务」这类否定事实 | 最窄档折叠 |
| 每张卡 | 逐卡方块，下面一行 `型号 × 张数`；委托集群没有逐卡库存，只写卡型；两者都没有的主机改写核数与内存总量 | 中档起折叠 |
| 空闲 | `可申请数 / 总卡数`；有冲突卡时数字转告警色 | 否 |
| GPU、显存、CPU、内存 | 每项都是「百分比在上，压力柱在下」，GPU 有近 1 小时数据时小曲线代替压力柱 | 否 |

**四项指标都有可比较的图形，没有主次之分。** 曾经把 CPU 与内存降级成纯数字，理由是「四条等权柱会让这一行读成四个同等重要的问题」；这个理由不成立——排序表头允许按 CPU 负载排序，排序依据却没有对应的可视量，而且不能横向比较的百分比等于没有百分比。压力柱的颜色阈值是唯一的分级手段：`<70%` 灰 / `<90%` 橙 / `≥90%` 红。

**表头就是排序控件。** 八个列头各自是一个排序键，当前键加深并带箭头；再次点击同一个列头反转方向。工具栏的排序菜单是窄窗口下折叠列的补充入口，不能取代表头。列头必须带辅助功能名称（`按<列名>排序`）——旧版表头没有名称，只有屏幕阅读器读得到的空按钮。

排序在每组内对登录入口、普通服务器与节点行统一执行，取该列的实际显示值。
`—`、`按需` 等没有数值的行在升序、降序中都放最后；相同值按连接地址与节点名自然排序。
切换排序或升降序后回到顶部，刷新数据保留当前位置。

**一行两层，不再多。** 放不下的一切都进 tooltip 和详情弹窗：远端工作区路径、服务器组路径与环境说明、逐卡显存、完整租约列表、峰值温度。分组段头不是第二行：它切断表格，不改变服务器行的高度或列对齐。

### 只放在详情里的信息

以下事实不进表格行；行的 tooltip 也保留一份：

| 事实 | 详情里的落点 | 不上表格行的理由 |
| --- | --- | --- |
| CPU 核数、内存总量 | `主机`卡片 | 静态硬件清单，不随刷新变化，不需要每次重读 |
| 最高温度 | `主机`卡片 | 健康信号而非分配信号，属于历史图那一侧 |
| 显存合计（绝对 GB） | 逐 GPU 卡的绝对显存 | 与同一行上的显存占用率直接重复 |
| 远端工作区完整路径 | 组卡片；未分组时用独立的`工作区`卡 | 在行里只能截成 `…workspace/tmp/user`，截断后不携带任何信息 |
| 服务器组默认路径、环境说明、组说明 | 组卡片 | 用来判断该不该选这组，不是比较这一行能不能申请；组管理与详情一次给全 |
| 申请约束：分配方式、租约如何结束与时限、一次最多卡数、每卡 CPU / 内存、申请等待上限 | 组卡片；未分组时用独立的`申请约束`卡 | 决定实验能不能放这个集群跑，但对同一集群的每台机器都一样，逐行重复没有信息 |
| 逐卡显存与任务 | 逐 GPU 卡 | 需要环图才能表达；详情里有宽度 |

判断标准是：**这条信息会改变「要不要用这台机器」的答案吗？** 会，就上表格行；只是用来确认或排查，就进详情。

**同一事实只出现一次。** 已经在表格行上的 CPU 负载、内存占用率与 GPU 型号，不在`主机`卡片里重复；组名与工作区只在组卡片出现，不在`主机`卡片再写一遍；GPU 状态四分类由网格顶部的计数承担，逐卡状态标签只在非`空闲`时出现。

工作区未设置是例外——它是可执行的告警，留在行里，并在详情里保留独立提示条；已设置的路径只是事实，放在组卡片或`工作区`卡里一次，不再占一条整宽横幅。

服务器页的四项资源指标和对应排序统一标示为**近 10 分钟均值**；GPU、主机 CPU 负载与主机内存都来自同一滚动观察窗口。没有该窗口数据时显示`—`，不得以瞬时值替代。逐 GPU 显存环图以打开详情时的瞬时观测绘制。

### 状态用语

| 状态 | GUI 用语 |
| --- | --- |
| 可参与新分配 | `空闲` |
| 有项目任务 | `任务占用` |
| 已申领但尚未观察到任务 | `占卡`，仍属于已分配资源，不等于空闲卡 |
| 未托管进程 | `未归属占用` |
| 明确归属冲突 | `归属冲突` |
| 无新观测 | `采集延迟` / `连接失败`（远端那一跳）或 `本机未更新`（本机控制面那一跳） |
| 委托集群，没有逐卡库存 | `按需申请 · 一次最多 N 卡`。N 是**一次能拿到的最大卡数**，不是池子剩余总数；两者混写会让人以为凑得齐实际凑不齐的卡数。取不到 N 时只写 `按需申请`，不得回退成剩余总数。这类服务器不是 `CPU 节点` |

禁止使用泛化的`待处理`、`快照过期`、`fail-closed`或`允许延迟`。正常状态不显示说明段落；异常只显示原因和可执行下一步。

## 6. 服务器详情

详情以独立桌面弹窗打开，按以下顺序排列：

1. 状态、更新时间与完整 SSH 指令
2. 紧凑操作栏：申请 GPU、开始 / 结束占卡，以及「编辑或移除服务器」
3. 仅在异常或需要人工回收时的说明与操作：工作区未设置、遗留占卡、归属冲突。不重复显示独立的占卡摘要，也不为已设置的工作区留一条整宽横幅
4. `主机`卡片：CPU 核数、内存总量、最高温度。**只放表格行刻意不显示的事实**——CPU 负载、内存占用率和 GPU 型号已经在行上，不在这里重复；三项都缺时整张卡不出现。若已加入服务器组，另给一张组卡片：显示名称、申请约束、组默认路径、是否使用本机路径覆盖、环境说明和组说明；未分组但有申请约束或已设置工作区时，用一张独立卡承担同样的内容
5. 逐 GPU 显存状态：整块使用与服务器页相同的磁贴容器；弹窗本身站在同一层页面平面上，不使用半透明材质。逐卡网格的最小列宽必须容得下环形图、编号、状态标签、绝对显存、任务行和百分比，否则每一项都会被截断在词中间。顶部以紧凑计数展示`空闲 / 占卡 / 繁忙 / 错误`，下面恢复逐 GPU 横向信息卡。每张卡左侧使用约 40 pt 的环形图，沿用旧版逐卡组件的圆角端点、内圈浅色填充和 GPU 编号；环的当前填充比例与绿 / 黄 / 红颜色沿用资源表显存占用率阈值。右侧只保留状态标签、当前显存量和占用百分比，不显示型号、UUID 或任务叙述。不得使用四张等权彩色状态面板，也不得把全部 GPU 合并成一张状态饼图
6. 历史图与 `1h / 6h / 24h`，固定为 CPU、内存、GPU 利用率和显存占用率的 2×2 排列

详情不能挤压服务器列表，也不能在宽窗口退化为右侧 inspector。弹窗优先给逐 GPU 状态图、历史图和操作留出宽度；关闭按钮与 Escape 都能退出。`开始占卡` / `结束占卡`只切换 ServerPilot 的逐卡空闲占卡策略：不得暗示会停止已有任务；结束前必须说明该事实并确认。若工作负载租约卡在 `CONFLICT`，显示`清理遗留归属`，先做一次新鲜采集，只有确认所有相关 GPU 都没有进程时才释放。

逐卡策略必须隔离故障：一张 GPU 处于冲突、忙碌或 stale 时，只跳过该卡，不能把同一服务器的其它空闲 GPU 一并标成不可启动。详情页对遗留租约提供人类可见的回收动作；它依据新鲜进程观测，不把 0% 利用率单独当作“没有任务”。

历史图包括 CPU、内存、GPU 利用率和显存占用率。多张 GPU 使用稳定的不同颜色，**整个面板只画一份 GPU 图例**，放在 2×2 网格之外：GPU 利用率与显存占用率用的是同一组颜色，各画一份等于把同样的对照表读两遍。CPU 与内存只有一条线，不画图例。图表自带的自动图例一律关闭。采样中断时折线必须断开；缺值不能补成 0。悬停只显示当前时间点的必要值。

## 7. 任务页

- 页面标题：`任务`，下面一行写任务数和占用卡数。
- 每个任务一张卡，按 `需要留意`（持有但没有进程）、`运行中` 分区，需要留意的在前。项目几乎全是同一个 Agent 项目时，按项目分组什么也说明不了，所以不做左右分栏。
- 卡片内容：任务名与状态、`持有者 · 项目`、三个数字（张卡、已运行或已持有、声明时长或没有进程的时长）、每台服务器一行逐卡方块、`归还` 与 `改派`。
- 右侧曲线是**所在服务器**近 1 小时的 GPU 利用率，标题写明「所在服务器」，因为没有哪个数据测量单个任务独占的份额。
- 空状态只显示：`当前没有资源分配。`，并提供`申请 GPU`。
- 不提供消息、协调链接、聊天或历史任务流水。

## 8. 设置页

按卡片分组，每组一张磁贴，组标题说明这一组的事实是关于什么的：

- `本机服务`：`服务地址`、`版本`
- `数据状态`：`连接`、`快照`（新鲜度与修订号）、`清单`（服务器 / GPU / 租约计数）、`资源变更`（可执行，或不可执行的具体原因）
- `数据采集`：`采集间隔`：`5 秒 / 10 秒 / 30 秒`

只读测试夹具会报告自己已连接，所以`连接`必须先判断是否可刷新，否则会声称连上了一个并不存在的本机服务。设置页的卡片列宽度有上限，但必须靠左对齐，不能在宽窗口里居中。

采集间隔是持久化设置。写入成功后才更新界面值；失败时保留旧值并显示一条具体错误。测试夹具可以展示实际值，但必须只读，不能伪装写入成功。

## 9. 表单、错误与确认

- 添加服务器：以 SSH 指令为主要输入，不重复展示可从指令直接读出的 host、port、user。可选择服务器组；默认继承组路径，也可为本机填写路径覆盖。
- 申请 GPU：存在正式服务器组时先选组，由控制面在组内选择服务器，不鼓励指定某一台。未分组主机保持原有路径。说明文字仅跟随字段错误。
- 服务器组：从服务器页维护显示名、创建时的分组标识、默认绝对路径、环境说明和描述；环境说明只给操作者阅读，不进入采集或远端进程。
- 错误：一句说明发生了什么，一句说明下一步。不要同时堆叠 banner、卡片和状态标签。
- 空状态：一句事实 + 一个主动作。
- 删除服务器放在编辑页底部「危险操作」区；确认框以取消为默认，并说明只停止本机监控/协调、不停止远端进程。预约与维护公共页只读，不提供创建或取消表单。

## 10. 交互与可访问性

- 搜索、筛选、所有可排序表头、服务器行、服务器组管理、返回按钮和主要动作均可键盘到达。
- 每个图标按钮提供可访问名称；指标提供文字值与单位。
- 焦点环使用原生样式，不用颜色变化替代焦点。
- 关闭装饰性动画。状态刷新使用无位移更新；Reduce Motion 下不得依赖动画解释变化。
- 最小验收视口为 1024×640，同时检查 1280×800 与 1440×820。截图验收用 `dashboard` 夹具（全部虚构），它带节点用量、任务、提醒和趋势数据。

## 11. 数据与能力边界

- App 只消费 loopback REST/domain 状态，不直连 SQLite 或 SSH。
- stale、unknown、unmanaged、conflict 和 maintenance 资源不参与分配。
- lease 协调归属，不启动、停止或抢占项目任务。
- Adapter ID 只用于诊断 provenance，不成为 GUI 工作流或资源身份。

任何新增页面、字段或说明，都必须回答一个问题：它是否直接帮助用户看清、申请或追溯资源。不能回答时，不加入 GUI。
